15  Tableros de control

En este capítulo se explica qué es un tablero de control y cómo construir uno con Quarto Dashboards, la capacidad de Quarto que permite combinar mapas, gráficos estadísticos y tablas en una sola interfaz. El capítulo culmina con un tablero de control completo y ejecutable sobre la riqueza de especies de félidos de Costa Rica, que reutiliza los datos y las visualizaciones del Capítulo 13 y del Apéndice A.

15.1 Resumen

Un tablero de control presenta diversas visualizaciones de datos (tablas, gráficos, mapas, etc.) de manera conjunta, distribuidas en arreglos de filas y columnas. Pueden contar con barras de navegación, barras de herramientas, páginas, pestañas (tabs) y cajas de valor (value boxes) que destacan indicadores clave. Con Quarto Dashboards, un tablero puede publicarse como una página estática (ej. en GitHub Pages) a partir de un documento .qmd con el formato dashboard.

15.3 Introducción

Un tablero de control, también llamado cuadro de mando o dashboard, es un tipo de interfaz gráfica de usuario que reúne visualizaciones de datos e información resumida relevantes para una temática, objetivo o proceso particular. Estas visualizaciones se presentan principalmente en formato de tablas, gráficos estadísticos y mapas. El término dashboard hace referencia al tablero de indicadores de un automóvil, el cual le permite al conductor monitorear rápidamente las funciones principales del vehículo (velocidad, combustible, etc.).

Los tableros de control son usualmente accesibles mediante un navegador web y pueden estar vinculados a fuentes de datos que se actualizan regularmente. Se caracterizan por ser interactivos y facilitar la exploración de datos a los usuarios.

Quarto facilita el desarrollo de tableros de control a través de Quarto Dashboards.

15.4 Quarto Dashboards

Quarto Dashboards es una capacidad de Quarto que permite crear tableros de control mediante los lenguajes de programación R, Python, Julia y Observable. Estos tableros de control pueden incluir componentes desarrollados en DT, Ggplot2, Plotly y Leaflet, entre otros paquetes de R. Pueden publicarse como páginas estáticas (ej. en GitHub Pages) o en un servidor Shiny para proporcionar mayor interactividad al usuario.

La Figura 15.1 muestra un tablero de control desarrollado con Quarto Dashboards.

15.4.1 Componentes

Un tablero de control desarrollado con Quarto Dashboards tiene los siguientes componentes:

  1. Barra de navegación: incluye el título, íconos y autor junto con enlaces a páginas (si se definen más de una página).

  2. Páginas, filas, columnas y pestañas (tabs): Las páginas, filas y columnas se definen utilizando encabezados de Markdown (con atributos opcionales para controlar la altura, el ancho y otras propiedades). Las pestañas pueden usarse para dividir aún más el contenido de una fila o columna.

  3. Tarjetas, barras laterales y barras de herramientas: Las tarjetas son contenedores para visualizaciones de datos como tablas, gráficos estadísticos, mapas y otras. Las barras laterales y barras de herramientas se utilizan para el ingreso de datos en tableros de control interactivos.

15.4.2 Configuración

Los tableros de control son arreglos de componentes que se utilizan para proporcionar navegación y presentar datos. A continuación, se describen los elementos que se utilizan para estructurar la navegación y el diseño de los tableros de control.

15.4.2.1 El formato format: dashboard

Un tablero de control se especifica en un documento Quarto (.qmd) cuyo encabezado YAML declara el formato dashboard. El resto del documento se organiza con encabezados de Markdown (para las filas, columnas y páginas) y celdas computacionales (para las tarjetas):

---
title: "Mi tablero de control"
author: "Autora o autor"
format: dashboard
---

15.4.2.2 Navegación

Todos los tableros de control tienen una barra de navegación que muestra el título y, opcionalmente, un logotipo, el nombre del autor e íconos con enlaces a redes sociales y otros sitios de interés. Los tableros de control con múltiples páginas también contienen un enlace a cada página en la barra de navegación. Los íconos de la barra se configuran con la opción nav-buttons y se toman de la colección Bootstrap Icons.

15.4.2.3 Filas y columnas

Dentro de una página, los componentes del tablero de control se organizan mediante conjuntos alternos de filas y columnas, definidos con encabezados de Markdown. La opción orientation del YAML determina si los encabezados de nivel 2 (##) crean filas (orientation: rows, el valor por defecto) o columnas (orientation: columns). El tamaño relativo de cada fila o columna se controla con los atributos {height=...} y {width=...}. En el siguiente ejemplo, la primera fila ocupa el 30 % de la altura y la segunda el 70 %:

15.4.2.4 Páginas

Para introducir múltiples páginas, se utilizan encabezados de nivel 1 sobre los encabezados de nivel 2, los cuales se usan para definir filas y columnas. El texto de los encabezados de nivel 1 se usa para enlazar a las páginas en la barra de navegación.

15.4.2.5 Pestañas

Las pestañas (tabs) se utilizan para incluir múltiples vistas de datos o contenido de importancia secundaria sin que interfiera con la visualización principal. Las pestañas se crean añadiendo la clase .tabset a una fila o columna; cada tarjeta dentro de ella se convierte en una pestaña:

### Column {.tabset}

```{r}
#| title: "Primera vista"
# ... código de la primera pestaña ...
```

```{r}
#| title: "Segunda vista"
# ... código de la segunda pestaña ...
```

15.4.2.6 Barras laterales

Una barra lateral (clase .sidebar) es una columna estrecha, usualmente a la izquierda, destinada a texto explicativo, leyendas o —en tableros interactivos con Shiny— a los controles de entrada del usuario. Se crea aplicando la clase .sidebar a un encabezado de nivel 1:

# {.sidebar}

Texto, leyendas o controles de entrada.

# Contenido principal

El uso de barras laterales con controles interactivos (listas de selección, deslizadores, etc.) requiere un tablero con interactividad mediante Shiny.

15.4.2.7 Tarjetas

Las tarjetas son la unidad fundamental de visualización en un tablero de control. Constituyen el contenido de las filas y las columnas. Cada celda computacional (bloque de código) genera automáticamente una tarjeta, y la opción de bloque #| title: le asigna un título a esa tarjeta.

15.4.2.8 Cajas de valor

Una caja de valor (value box) es una tarjeta especial que destaca un único indicador numérico, acompañado de un título, un ícono y un color. Se crea con la opción de bloque #| content: valuebox, devolviendo una lista con los elementos title, value, icon y color:

```{r}
#| content: valuebox
#| title: "Registros de presencia"
list(
  icon  = "binoculars",
  color = "primary",
  value = 2007
)
```

15.4.2.9 Cómo embeber mapas y tablas

Cualquier mapa (leaflet, tmap en modo view), gráfico (plotly, ggplot2) o tabla (DT) que sea la salida de una celda computacional se convierte automáticamente en el contenido de una tarjeta. Para que los mapas tmap resulten interactivos dentro del tablero, conviene activar el modo de visualización con tmap_mode("view").

Para más información sobre la configuración de los tableros de control, se recomienda consultar Dashboard Layout.

Como ejemplo integral, se construyó un tablero de control que resume la riqueza de especies de félidos silvestres de Costa Rica. El tablero es un documento Quarto independiente (con format: dashboard) que se renderiza y publica como página estática en GitHub Pages:

15.7.1 Estructura del tablero

El tablero tiene una sola página con orientación por filas (orientation: rows) y se organiza en tres filas:

  • Fila superior (15 % de la altura): tres cajas de valor con los indicadores principales —el total de registros de presencia, el número de especies y las áreas de conservación con mayor riqueza (junto con esa riqueza máxima)—.
  • Fila central (55 % de la altura): dos columnas.
    • La columna izquierda (60 % del ancho) contiene tres pestañas con mapas: el mapa de registros agrupados, el mapa de calor y el mapa de coropletas de riqueza por área de conservación.

  • Fila inferior (30 % de la altura): una tabla interactiva (DT) con los registros de presencia de félidos a nivel individual.

15.7.4 Simplificación de las geometrías para los mapas

Los polígonos de las áreas de conservación tienen contornos muy detallados (siguen la línea de costa y los límites naturales), con más de 340 000 vértices en total. Como el tablero los dibuja en tres mapas y cada mapa de leaflet incrusta la geometría dentro del propio archivo HTML, esa versión detallada haría que el HTML superara los 50 MB, con la consiguiente lentitud de carga.

Para evitarlo se genera una versión simplificada de los polígonos, siguiendo la técnica de st_simplify() vista en el Capítulo 14. Como el argumento dTolerance se expresa en las unidades del CRS, se proyecta la capa al CRS métrico de Costa Rica CRTM05 (EPSG:5367), se simplifica con una tolerancia de 500 m y se regresa a WGS84 (EPSG:4326), que es el CRS que requiere leaflet:

```{r}
# Versión simplificada de las áreas, solo para dibujarlas en los mapas
areas_conservacion_simplificadas <-
  areas_conservacion |>
  st_transform(5367) |>                               # CRTM05 (metros)
  st_simplify(dTolerance = 500, preserveTopology = TRUE) |>
  st_transform(4326)                                  # de vuelta a WGS84
```

Esta simplificación reduce los vértices de unos 340 000 a unos 2 000 (cerca de un 99 % menos) y el tamaño del HTML de más de 50 MB a unos 3 MB, sin diferencia perceptible a la escala del mapa.

¿Por qué no afecta al análisis? Porque la simplificación se usa únicamente para dibujar los polígonos. El cálculo de la riqueza se hace antes, con la unión espacial sobre las geometrías originales: st_join() asigna cada registro de félido al área que lo contiene usando los bordes completos, de modo que ningún punto cambia de área por la generalización. La capa simplificada solo recibe después, mediante una unión por atributo (left_join() por codigo_ac), el valor de riqueza ya calculado. Los conteos por área son idénticos con o sin simplificación; lo único que cambia es el nivel de detalle del contorno que se muestra.

15.7.6 Mapas

La columna izquierda se declara como .tabset para que cada mapa ocupe una pestaña. El mapa de registros agrupados y el mapa de calor se construyen con leaflet y leaflet.extras (técnicas vistas en el Capítulo 13), mientras que el mapa de coropletas de riqueza usa tmap (como en el Apéndice A):

### Column {width=60% .tabset}

```{r}
#| title: "Registros agrupados"
leaflet() |>
  setView(lng = -84.2, lat = 9.6, zoom = 7) |>
  addProviderTiles(providers$OpenStreetMap, group = "OpenStreetMap") |>
  addProviderTiles(providers$CartoDB.Positron, group = "CartoDB Positron") |>
  addPolygons(data = areas_conservacion_simplificadas, weight = 1, color = "black", fillOpacity = 0,
              label = ~nombre_ac, group = "Áreas de conservación") |>
  addMarkers(data = felidos, label = ~species,
             clusterOptions = markerClusterOptions(), group = "Félidos") |>
  addLayersControl(baseGroups = c("OpenStreetMap", "CartoDB Positron"),
                   overlayGroups = c("Áreas de conservación", "Félidos")) |>
  addScaleBar(position = "bottomleft")
```

```{r}
#| title: "Mapa de calor"
```

15.7.7 Gráfico

La columna derecha contiene un gráfico de barras horizontales con la riqueza de félidos por área de conservación. Siguiendo el flujo visto en el Capítulo 10, el gráfico se construye primero con ggplot2 y luego se convierte en interactivo con ggplotly():

### Column {width=40%}

```{r}
#| title: "Riqueza por área de conservación"
grafico_riqueza <-
  areas_union_riqueza |>
  st_drop_geometry() |>
  ggplot(aes(
    x = riqueza_especies_felidos,
    y = reorder(siglas_ac, riqueza_especies_felidos)
  )) +
  geom_col(
    fill = "#41ab5d",
    aes(text = paste0(
      "Área de conservación: ", nombre_ac, "\n",
      "Riqueza de félidos: ", riqueza_especies_felidos
    ))
  ) +
  ggtitle("Riqueza de especies de félidos por área de conservación") +
  xlab("Riqueza de especies de félidos") +
  ylab("Área de conservación") +
  theme_minimal()

ggplotly(grafico_riqueza, tooltip = "text") |>
  config(locale = "es")
```

15.7.9 Publicación

Como el libro es un proyecto Quarto de tipo book, el tablero no se incluye en el índice (_quarto.yml): es un documento independiente que se renderiza por separado con quarto render tableros/tablero-riqueza-felidos.qmd. Su salida (tablero-riqueza-felidos.html) se ubica en docs/tableros/, junto al resto del sitio publicado en GitHub Pages, y se enlaza desde este capítulo mediante una ruta relativa.
